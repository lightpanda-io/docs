# JavaScript SDK

See the [package README](https://github.com/lightpanda-io/lightpanda-js#readme) for a practical walkthrough. The package is ESM with TypeScript declarations; every type named below is exported from `'lightpanda'`.

Browser actions are methods on [`Session`](#session), named after the browser's own action names, each taking one options object with the action's arguments: `page.waitForSelector({ selector: '.done' })`. The arguments of each method are listed under it.

Where a method accepts both `selector` and `backendNodeId`, pass one of the two. `selector` is preferred for reproducibility and wins when both are given; `backendNodeId` takes the values returned by [`tree`](#session-tree), [`links`](#session-links) or [`findElement`](#session-find-element).

### Session.evaluate [#session-evaluate]

```ts
evaluate(args: EvaluateArgs): Promise<unknown>
```

Evaluate JavaScript in the current page context — an escape hatch for page-side logic the dedicated tools can't express; prefer `extract` for data and click/fill/etc. for actions. It runs in the page, so it cannot see the agent script's variables or builtins — interpolate any value into the `script` string. A bare trailing expression yields its value; top-level `await` and `return` are supported (the body then runs as an async function, so use `return` to produce a value). Objects and arrays return as JSON, so no `JSON.stringify` is needed. If a url is provided, it navigates there first. The `globalThis.lp` object exposes a Session-scoped bridge store: values written via `lp.foo = ...` auto-sync at end of evaluate, surviving navigation; values previously set via `/extract save=` or `/evaluate save=` appear as `lp.<name>`.

**Arguments** (`EvaluateArgs`):

- `script: string`
- `save?: string`: Optional bridge-store key. The evaluate's return value is stored under this name and re-exposed as `lp.<name>` to subsequent evaluates. Objects, arrays, and strings are serialized automatically — no JSON.stringify needed.
- `timeout?: number`: Optional timeout in milliseconds. Defaults to 10000.
- `url?: string`: Optional URL to navigate to before evaluating.

### Session.extract [#session-extract]

```ts
extract(args: ExtractArgs): Promise<unknown>
```

Extract structured data from the current page (navigate first). `schema` is a JSON object (passed as a string) mapping output field names to CSS-selector specs. It is NOT a JSON Schema — no "type"/"properties" wrappers; the keys ARE your output fields. Value shapes:
  "&lt;sel>"                                → first match's text (trimmed; null if no match)
  ["&lt;sel>"]                              → every match's text (string[])
  \{"selector":"&lt;sel>","attr":"&lt;name>"\}   → first match's attribute value (href/src resolved to absolute URLs)
  [\{"selector":"&lt;sel>","attr":"&lt;name>"\}] → every match's attribute (string[])
  [\{"selector":"&lt;sel>","fields":\{…\}\}]    → one object per match; field selectors resolve relative to that match and accept any shape above ("" = the match's own text; nest arrays for per-item sub-lists)
Add "limit": N inside any array's object spec to cap matches.
Every extracted value is a string or null — parse numbers downstream. An empty array is a valid result, but if ALL top-level keys miss, the call errors: inspect the page (tree/markdown) and retry with corrected selectors.
Finish data tasks with extract — it is the only read recorded as a replayable `extract(...)` script call; answers lifted from `markdown` text in chat are not.

Examples (schema → result):
  \{"karma": "#karma"\} → \{"karma":"42"\}
  \{"items": [".story .title"]\} → \{"items":["Title 1","Title 2"]\}
  \{"top3": [\{"selector":".story .title","limit":3\}]\} → \{"top3":["A","B","C"]\}
  \{"links": [\{"selector":"a.title","attr":"href"\}]\} → \{"links":["https://site/a","https://site/b"]\}
  \{"stories": [\{"selector":".athing","fields":\{"title":".titleline","rank":".rank"\}\}]\} → \{"stories":[\{"title":"Foo","rank":"1"\}]\}

**Arguments** (`ExtractArgs`):

- `schema: string | Record<string, unknown> | unknown[]`: Extraction schema as a string: a JSON object literal mapping output field names to CSS-selector specs (see tool description). Not a JSON Schema.
- `save?: string`: Optional bridge-store key. The extracted JSON is stored under this name and exposed as `lp.<name>` in subsequent /evaluate calls.

### Session.waitForState [#session-wait-for-state]

```ts
waitForState(args: WaitForStateArgs): Promise<unknown>
```

Wait for the CURRENT page to reach a load state (no navigation). After a `goto`, the page is returned at the fast `load` snapshot, so content rendered by post-load JS (XHR-loaded lists, feeds, search results) may still be missing. **Arguments** (`WaitForStateArgs`):


*Property.* The session-less BiDi WebSocket URL, `ws://<host>:<port>/session`, for
clients that speak BiDi directly. A session bootstrapped through
`POST /session` gets its own socket at `<bidiEndpoint>/<sessionId>`,
returned as the `webSocketUrl` capability.

### BiDiServer.status [#bidiserver-status]

```ts
status(): Promise<{ ready: boolean; message: string }>
```

The `GET /status` value, `{ ready: true, message: '' }`.

## fetch [#fetch]

```ts
function fetch(url: string, options?: Omit<FetchOptions, 'dump'> & { dump?: 'html' | 'markdown' | 'semantic_tree' | 'semantic_tree_text' }): Promise<string>
function fetch(url: string, options: Omit<FetchOptions, 'dump'> & { dump: 'png' | 'pdf' }): Promise<Buffer>
```

Load `url` once and return the dump: a string for the text formats, a
`Buffer` for `'png'` and `'pdf'`.

```js
import { fetch } from 'lightpanda'
const markdown = await fetch('https://lightpanda.io', { dump: 'markdown' })
```

Rejects with [`RunError`](#runerror) when the browser exits non-zero or is killed by
`timeout` (its `exitCode`, `signal`, `stdout` and `stderr` carry the
detail), [`ProcessError`](#processerror) when there is no binary, and [`LightpandaError`](#lightpandaerror) on a
mistyped browser option. Note that by default a page answering 404 is still
dumped; pass `args: ['--fail-on-http-error']` to make that an error.

## runScript [#runscript]

```ts
function runScript(script: string, options?: RunOptions & BrowserFlags): Promise<string>
```

Replay a saved lightpanda script (no LLM) and return its stdout.

`env` entries (e.g. `LP_*` placeholder values) are added to the child's
environment; the typed browser options ([`BrowserFlags`](#browserflags)) apply to the
replay, and `args` are extra `lightpanda run` flags. Rejects with [`ScriptError`](#scripterror) on a non-zero exit or a `timeout`
kill, and with [`LightpandaError`](#lightpandaerror) on a mistyped browser option.

**Parameters:**

- **script**: Path to the script file.

## findBinary [#findbinary]

```ts
function findBinary(explicit?: string): string
```

Locate the lightpanda binary: the explicit path, `$LIGHTPANDA_BIN`, the
bundled platform package, then `PATH` (skipping this package's own bin
shim, which shadows a real binary when `node_modules/.bin` comes first).
Throws [`ProcessError`](#processerror) when none of them is a file.

## bundledBrowserVersion [#bundledbrowserversion]

```ts
function bundledBrowserVersion(): string | undefined
```

The version of the browser bundled with this install: the platform package's
version, which is the browser release it carries. `undefined` when no
platform package is installed (a `LIGHTPANDA_BIN` or PATH binary is not
looked at).

## Options and types [#options-and-types]

### BrowserFlags [#browserflags]

```ts
interface BrowserFlags
```

Browser settings every launcher and run takes, as typed options: each
becomes the `lightpanda` flag of the same name (`obeyRobots` →
`--obey-robots`). Flags not listed here go through `args`, which comes
after them on the command line.

- `obeyRobots?: boolean`: Fetch and obey the target site's robots.txt.
- `insecureDisableTlsHostVerification?: boolean`: Accept any TLS certificate. For self-signed test servers only.
- `blockPrivateNetworks?: boolean`: Block requests to private and internal addresses, checked after DNS resolution.
- `httpProxy?: string`: Proxy URL for all requests; `username:password@` may be included for basic auth.
- `proxyBearerToken?: string`: Sent as `Proxy-Authorization: Bearer <token>`.
- `userAgent?: string`: Replace the User-Agent entirely. The browser refuses values that impersonate other browsers (containing "Mozilla").
- `userAgentSuffix?: string`: Appended to the default User-Agent.
- `locale?: string`: BCP 47 tag for `navigator.language`, `Accept-Language` and `Intl`, `en-US` by default.
- `timezone?: string`: IANA time zone for `Date` and `Intl`, e.g. `Europe/Paris`; the host's by default.
- `httpCacheDir?: string`: Directory for a persistent HTTP cache.
- `httpTimeout?: number`: Milliseconds a transfer may take, 15000 by default; 0 means never time out.
- `loadResources?: ('image' | 'iframe' | 'worker' | 'stylesheet')[]`: Sub-resources to actually request; none by default. `'stylesheet'` makes external CSS count for computed styles and visibility.
- `blockUrls?: string[]`: URL patterns to block, matched case-insensitively against the full URL, `*` as wildcard.
- `httpHeaders?: Record<string, string>`: Extra headers on every request. `User-Agent` goes through `userAgent` instead.

### LaunchOptions [#launchoptions]

```ts
type LaunchOptions = ProcessOptions & BrowserFlags & { timeout?: number }
```

Options for [`Browser.launch`](#browser-launch): [`ProcessOptions`](#processoptions) and
[`BrowserFlags`](#browserflags), plus `timeout`, the milliseconds to wait for a
response to any request (default 300000). The browser options apply to
every session.

### ProcessOptions [#processoptions]

```ts
interface ProcessOptions
```

Process options of the long-lived browsers ([`Browser.launch`](#browser-launch),
[`CDPServer.launch`](#cdpserver-launch), [`BiDiServer.launch`](#bidiserver-launch)).

- `binary?: string`: Path to a lightpanda binary. When omitted, resolved from `LIGHTPANDA_BIN`, then the bundled platform package, then `PATH`.
- `env?: Record<string, string>`: Extra environment variables for the child.
- `args?: string[]`: Extra CLI flags for the child, after the typed browser options, e.g. `['--http-max-concurrent', '10']` or `['--cookie', path]`.
- `verbose?: boolean`: Let the browser's own logging through to stderr.

### FetchOptions [#fetchoptions]

```ts
type FetchOptions = RunOptions & BrowserFlags & { dump?: FetchDump }
```

Options for [`fetch`](#fetch): [`RunOptions`](#runoptions) and [`BrowserFlags`](#browserflags), plus
`dump`, what to write: `'html'` (the default), `'markdown'`,
`'semantic_tree'` or `'semantic_tree_text'` as a string, `'png'` or
`'pdf'` as a `Buffer`.

### FetchDump [#fetchdump]

```ts
type FetchDump = 'html' | 'markdown' | 'png' | 'pdf' | 'semantic_tree' | 'semantic_tree_text'
```

What [`fetch`](#fetch) writes: the text formats come back as a string, `'png'`
and `'pdf'` as a `Buffer`.

### RunOptions [#runoptions]

```ts
interface RunOptions
```

Process options of the one-shot runs ([`fetch`](#fetch), [`runScript`](#runscript)).

- `binary?: string`: Path to a lightpanda binary. When omitted, resolved from `LIGHTPANDA_BIN`, then the bundled platform package, then `PATH`.
- `env?: Record<string, string>`: Extra environment variables for the child.
- `args?: string[]`: Extra CLI flags for the child, after the typed browser options, e.g. `['--wait-until', 'networkidle']` for [`fetch`](#fetch).
- `timeout?: number`: Milliseconds before the child is killed.

### ServeOptions [#serveoptions]

```ts
type ServeOptions = ProcessOptions & BrowserFlags & { port?: number; host?: string; advertiseHost?: string }
```

Options for [`CDPServer.launch`](#cdpserver-launch) and [`BiDiServer.launch`](#bidiserver-launch):
[`ProcessOptions`](#processoptions) and [`BrowserFlags`](#browserflags), which apply to every
client of the server, plus:

- `port`: the listening port; a free one by default.
- `host`: the address to bind, `127.0.0.1` by default (`0.0.0.0` to accept
  connections from outside the machine, as the Docker image does).
- `advertiseHost`: the address the endpoints point at, for when clients
  reach the server somewhere other than the bind address (behind a
  published container port, say).

Pass these rather than `--port`/`--host`/`--advertise-host` in `args`.

### ToolSpec [#toolspec]

```ts
interface ToolSpec
```

A tool as the browser lists it, in [`Browser.tools`](#browser-tools).

- `description: string`
- `schema: Record<string, any>`: The tool's JSON schema for its arguments.

## Errors [#errors]

### LightpandaError [#lightpandaerror]

```ts
class LightpandaError extends Error
```

Base error for the lightpanda package, and what usage errors throw directly
(a call on a closed server, a mistyped browser option).

### ProcessError [#processerror]

```ts
class ProcessError extends LightpandaError
```

The browser binary could not be found, started, or reached.

### RunError [#runerror]

```ts
class RunError extends ProcessError
```

A one-shot run of the binary ([`fetch`](#fetch), [`runScript`](#runscript)) exited with a failure.

- `exitCode: number`: The exit status, or -1 when the binary was killed or could not be run.
- `signal: string | undefined`: The signal that killed the run, when one did (a `timeout`, say).
- `stdout: string`: What the run wrote to stdout before failing.
- `stderr: string`: What the run wrote to stderr.

### ScriptError [#scripterror]

```ts
class ScriptError extends RunError
```

A script replay ([`runScript`](#runscript)) exited with a failure.

### ProtocolError [#protocolerror]

```ts
class ProtocolError extends LightpandaError
```

JSON-RPC level failure (invalid request, timeout, internal error).

- `code: number | undefined`: The JSON-RPC error code, when the server sent one.

### ToolError [#toolerror]

```ts
class ToolError extends LightpandaError
```

A browser tool reported failure (bad selector, JS exception, ...).
